## 用同一个问题贯穿开发

可以从一个临床登记问题开始：“在本次取得的某疾病资料中，登记的干预名称、阶段、招募或停止状态有哪些差异，停止原因和结果还有什么待核实？”这只是问题示例，实际材料与发现以真实读取为准；名称相同还不等于已经完成对象身份核对。

本轮正在开发的最小链路是：限定词语查 Data-Fabric 已有标题，每轮最多 6 条；读取协议中的真实字段，从实际干预名派生最多 2 次查找，共不超过 3 轮、18 条采用材料。随后保存问题、每轮范围、材料、事实差异与缺口，输出可读记录。代码和真实运行验收完成前，不把它写成已有能力。

程序整理的说明写成笔记，材料先按上下文或待定保存；不能自动替研究人员签一版判断。“终止”不等于“疗效失败”，“本次没查到”不等于“没有相关研究”。只有来源允许、数据确实支持的部分才能往下做。

每人下面有五项递进任务。已有功能先跑懂、检查实际行为，再补具体缺口，不重写一遍。一次提交解决一个明确问题；依赖没完成时，先用明确标注的教学资料验证程序，真实能力继续标为待接通。

## 李明洋：让资料与服务可靠接进来

### 李1：沿着一次真实读取找全入口

目标是能解释一条来源记录怎样进入雷达，而不只是运行命令。先用获准的少量 UUID 读取，找到原文、来源标识、本次采用时间和缺少的字段。

- **先看文件：** `services/bioradar/ops/snapshot_data_fabric.py`、`adapters/data_fabric_snapshot.py`、`api/config.py`；对照 `tests/test_engine_adapters.py`。配置和密钥留在本地环境，不写进样例。
- **输入与输出：** 指定来源实例、许可和记录名单，输出现有 `NormalizedSnapshot` 资料包；内容引用保持来源、记录、版本和原文定位。日期不清就保留未知。
- **错误例与验收：** 一个 UUID 读取失败时，整批明确失败，旧文件不被空包覆盖；越权来源被拒绝；摘要缺正文时如实标明。核对引用能回到本次采用文本，并能说明它与原始全文有什么区别。
- **依赖与进阶：** 徐子雯提供可读原文和字段含义。完成后再做李2，不去修改她的采集流程或直接查询她的数据库来绕过接口。

### 李2：在已有接入上增加一种获准来源

本轮已经提供 ClinicalTrials 标题查找与协议读取的实现，验收后直接复用。下一项任务是与徐子雯选一种实际需要的新来源，例如已有 PubMed，先交清楚的输入输出和错误例，再接一条真实材料。不要重做已有标题搜索，也不要把临床协议解析套到论文上。

- **先看文件：** `adapters/data_fabric_research.py`；读取保护沿用 `adapters/data_fabric_snapshot.py` 的边界。当前上游入口为 Data-Fabric 的 `api/routers/research.py` 与 `biz_rules/clinical_research.py`，由徐子雯接续维护，不复制到雷达。新来源用具体适配函数，不建注册平台。
- **输入与输出：** 孙博文给出待查问题、来源与数量上限；徐子雯先给真实正文、日期与版本的例子。adapter 输出同一套采用资料与读取状态，原文范围不完整就保留缺口，不靠大模型补成完整论文。
- **错误例与验收：** 用新来源检查空命中、上限、超时、越权和错误版本；来源正文缺失不能返回空成功。采用一条真实记录后核对出处和定位，再让孙博文消费；不能仅因 HTTP 200 就宣布接通。
- **依赖与进阶：** 上游没有新来源接口时先交样例，不绕过服务读库。徐子雯负责事实与接口，孙博文负责查找如何派生，李明洋只做连接与转换；随后把有出处的材料用于 WeKnora 补查。

### 李3：让 WeKnora 返回能采用的证据

目标是接通一次实际补查，而不是再建搜索系统。例如对某登记中的停止理由，查找相关原始公告、论文或结果，说明在哪些获准范围里查过。

- **先看文件：** `adapters/exchange.py`、`adapters/provider_batch.py`、`adapters/registry.py` 和 `contracts/provider-exchange.schema.json`；真实调用放 `adapters/` 中一个具体适配文件。WeKnora 内的路由、检索与重排仍在其原工程维护。
- **输入与输出：** 输入具体问题、可读来源、截止时间和预算；返回带原出处、记录版本、定位及执行状态的材料。按现有交换格式采用，保存一次调用与其实际结果的对应关系。
- **错误例与验收：** 超时不能记成“无相关证据”；对端已有材料不等于当前账号能读；返回别的请求或别的资料版本必须拒绝。用一个真实成功、一个空命中和一个失败例子检查，确认 WeKnora 中保存的来源也能回读。
- **依赖与进阶：** 徐子雯确认传出的文档版本和同步回执，李明洋确认 WeKnora 的实际接收。接通后由孙博文决定是否继续补查，不能让检索服务自行代替雷达作研究判断。

### 李4：接续资料变化与旧版读取

目标是让“这条资料变了”有明确依据。先区分内容变更、旧资料补录和身份补充，再处理撤回、删除与许可变化。

- **先看文件：** `adapters/provider_batch.py`、现有来源 adapter、`contracts/provider-exchange.schema.json`；孙博文使用 `research/comparison.py` 消费结果，数据库迁移由李明洋维护。
- **输入与输出：** 上游提供稳定记录标识、内容版本及可继续读取的位置；输出能绑定前后两版的采用记录。雷达自己的冻结副本不冒充上游已支持旧版回读。
- **错误例与验收：** 两次并发发布反序提交也不漏读；重读不重复采用；撤权后不能继续从 API 读旧正文。下游读取失败不能被解释为来源删除，今天补录的旧试验不能成为今天的新研究。
- **依赖与进阶：** 徐子雯先完成版本和变更发布接口；唐蔚雯的身份更正带独立来源与时间。接口未完成时继续用显式批次，不先建第二套同步账本。

### 李5：让合并、运行和回退可重复

目标是三人的修改能在同一组版本上使用，出问题时保住研究记录。先维护这一个开发环境，再考虑更复杂的机构部署。

- **先看文件：** `Makefile`、`ops/compose.yaml`、`scripts/init_dev.py`、`db/migrations/`、`contracts/bioradar-engine.openapi.json`；研究运行规则仍由孙博文维护 `research/engine/`。
- **输入与输出：** 输入明确的代码提交、配置和数据备份；输出能启动的同版本 API/Worker、检查结果和可操作回退步骤。不要把本机凭据、真实材料或别的工程复制进 Git。
- **错误例与验收：** 停启后调查与旧结果不丢；Redis 中断不能把未执行计算写成完成；回退代码不删除数据卷，迁移恢复另行确认。必要时跑真实 PG/RQ 检查，保持 Data-Fabric 等共享任务不受影响。
- **依赖与进阶：** 收到孙、刘的非作者审阅通过后才合并。未来机构身份与项目权限由实际使用单位提供规则；当前开发账号不先包装成已完成的正式权限系统。

## 孙博文：让资料变成值得继续的调查

### 孙1：先讲清现有 11 类方法能回答什么

目标是能拿一个真实结果解释“为什么选它、凭什么、还缺什么”。先逐项看输入要求，只运行当前材料确实支持的方法。

- **先看文件：** `research/mining/registry.py`、`models.py`、`prepare.py`、`runner.py`，再看相应 `methods_text.py`、`methods_state.py` 等实现；对照 `tests/test_mining.py`。
- **输入与输出：** 输入采用资料与固定计算条件，输出候选、支持材料、未采用项和缺口。短语或主题可以在正文阶段探索；图谱、项目时间和专业评价缺失时，依赖它们的方法保持不可用。
- **错误例与验收：** JSON 键不能当正文主题；同篇转载不能变成独立证据；只有三个摘要不能声称领域增长。请研究人员检查已选候选，也抽查未选材料，说明是有价值、重复、无关还是资料不足。
- **依赖与进阶：** 李明洋提供可用文本；徐子雯声明覆盖范围；唐蔚雯确认身份。代码原样已满足的检查不为增加数量重写，先找一个实际有问题的结果，再做孙2。

### 孙2：从一个实际漏查改进已有派生查找

本轮已经提供按真实干预名抽取代码、派生下一查询及比较登记字段的实现，验收后直接复用。下一项任务是选一个实际漏查或无关查找，解释原因后只改相关策略。例如原名称和登记中写法不同，应先取得唐蔚雯的有源别名，而不是再造词典。

- **先看文件：** `research/investigations/digging.py` 的 `select_followups`、`summarize_trials`、`run_bounded_investigation`，以及已有 `research/investigations/models.py`。保留普通函数与现有调查保存，不加通用 Agent 或流程引擎。
- **输入与输出：** 输入明确问题、已读事实、必要的有源别名和预算；输出能回到原材料的下一查询及事实整理。相同输入结果应相同，纯函数不联网、不读时钟；实际请求由李明洋的 adapter 执行。
- **错误例与验收：** 偶然同词不能确认同一治疗；登记不证明药物有效；第二轮不能预写假词装成主动发现。用同一批资料对照修改前后的相关材料、漏查、重复和调用数，增加命中不自动算改进，预算和未决状态仍正确。
- **依赖与进阶：** 先复现本轮例子，再改一处真实缺口。别名依赖唐蔚雯；新来源依赖李2。条件未满足时保持原规则和未知，不为凑发现编候选，也不静默扩大用户的主题范围。

### 孙3：保留异议与判断为什么变化

目标是让别人看得懂一项研究判断及其反例，而不是只看到最新一句总结。已有调查保存先复用，重点检查材料与命题的关系。

- **先看文件：** `research/investigations/models.py`、`service.py`，以及 `tests/test_investigations.py`；专业评价数据已有类型在 `research/mining/models.py`，外部接入由李明洋处理。
- **输入与输出：** 输入本调查的材料、研究人员的分类和判断；输出当时依据、适用条件、署名、上一版判断及待复查状态。材料的资助、利益声明和反面观点应随来源保留，不能因客户用途不同改变事实。
- **错误例与验收：** 加入反面材料后，旧判断不动；新判断没纳入它仍需复查；不同人群或组别的结论不能互相代替。程序的风险提示只写笔记，不能伪称研究人员或汪鑫怡已认可。
- **依赖与进阶：** 研究人员先明确命题和适用条件，汪鑫怡提供专业评价，潘倩提供表述核验。未接通时展示未评价；以后才按实际依赖说明哪些新材料可能改变哪些判断。

### 孙4：从发现接到可讨论的方案

目标是回答“接下来能做什么”，同时说明采用了哪些假设。先复用现有方案比较，而不是给一个看似精确的综合分。

- **先看文件：** `research/decision/models.py`、`evidence.py`、`algorithms.py`、`runner.py`；看 `contracts/examples/decision-fixture.*.json` 及 `tests/test_decision.py`。
- **输入与输出：** 输入明确问题、维持现状等方案、预算条件、同口径数值区间和署名假设；输出门槛、相对差异、不可直接取舍项、情景风险及下一步待查问题。
- **错误例与验收：** 当前库存不能当未来产能；不同单位、时期和人群不能直接相减；有引用不等于数值已经专业核实。中央、地方、学校、企业可以改变委托目标和约束，同一来源事实保持不变，商业回报不替代公共价值。
- **依赖与进阶：** 研究人员给真实目标，李明洋接授权预算和能力资料，汪鑫怡等提供对应评价。现有四类用途教学例子只验证规则；成本效果、市场预测和政策因果模型尚需数据与专业方法。

### 孙5：让重要问题持续接受新证据检查

目标是从“一次调查”走到“有理由继续关注”。先明确哪些变化值得重看，再安排什么时候检查；不是每次新增文档都重写判断。

- **先看文件：** `research/comparison.py`、`research/mining/prepare.py`、`temporal.py`、`methods_impact.py`、`research/investigations/service.py`；需要后台执行时沿用 `research/engine/worker.py` 和现有 RQ。
- **输入与输出：** 输入旧材料与判断、上游确认的新版本、待查问题和研究人员给定的复查条件；输出需要重新检查的原因、相关材料、下一步及检查历史，保留旧依据。
- **错误例与验收：** 补录旧文、身份补充不冒充新突破；来源撤回后不能继续当有效支持；没有可靠可见时间的材料不能进入历史回放。自动通知只说明值得核实，不宣布判断已经改变。
- **依赖与进阶：** 李4与上游版本先完成。再以历史专题检验提前发现、漏报和误报，逐步做长期监测；目前不新增第三种 `analysis_runs` 或第二队列，也不宣称已经自动连续调查。

## 刘金彦：让人能读懂、核对并评价结果

目标是让读者不用看 JSON，也能找到问题、材料、判断及其变化。先操作已有教学记录，再请研究人员读一份真实材料。

- **错误例与验收：** 旧请求迟到不能覆盖当前记录；关闭再打开仍能看到已保存意见；旧版判断能逐项找到当时的材料。用窄屏检查内容和按钮，教学材料、未核验和读取失败都能辨认。

### 刘2：输出一份脱离网页也能阅读的记录

目标是命令执行完能交给研究人员看，读者能辨认查过什么、发现了什么和没证明什么。先交一份简单可读文件，再按实际需要增加格式。

- **先看文件：** `services/bioradar/delivery/` 当前只有包入口，面向读者的自动交付属于待补能力；`services/bioradar/ops/dig.py` 本轮将输出结构化调查 JSON。复用调查 `InvestigationView` 和现有记录组件的阅读顺序，不再建立另一套报告数据库。
- **输入与输出：** 输入当前有权限读取的调查与已有结构化结果，输出问题、查询范围、主要事实、来源定位、异议、已保存判断和未决事项。只做阅读展示，不另算一遍研究结论；程序整理和研究人员判断分别标明。
- **错误例与验收：** 没有判断就写尚无判断；来源只有部分协议就不叫完整报告。两版判断分别列实际依据，不只显示数量；导出前仍检查当前来源许可，不泄露本地文件路径、凭据或不必要的整份原文。
- **依赖与进阶：** 孙博文确定研究内容，李明洋提供授权读取。本轮两份工程修改报告由导师交付，不等于已经建成自动专业研报服务；将来再接潘倩的有据成文与核验。

### 刘3：做一个研究人员能实际使用的小评测集

目标是知道雷达比普通查找好在哪里、差在哪里。先选一个专题、少量问题，固定同样资料和时间，让独立研究人员给判断。

- **先看文件：** `evaluation/` 现有工程检查记录、`scripts/example.py` 和现有结果 API；在 `evaluation/` 增加具体专题的数据与普通评测脚本即可，不建通用评测平台。
- **输入与输出：** 输入真实问题、允许采用的资料、人工标注规则和各方法结果；输出有效线索、错误、重复、遗漏反例及实际审阅耗时。规则和专业标签由研究人员确定，刘金彦做采集与计算工具。
- **错误例与验收：** 不能只检查系统已经选出的材料，须抽查未选项；同研究不同版本或转载不能一份训练、一份验收。与现有 WeKnora、普通问答及人工研究在同一资料与预算下比较，失败和未完成也保留。
- **依赖与进阶：** 李明洋保留输入与版本，孙博文解释候选含义。先记录几十个可复核的真实判断，再讨论扩大样本；教学例子的自动检查不充当专业准确率。

### 刘4：用当时可知道的资料检查历史效果

目标是检查过去某时点系统会看到什么，以及后来事实是否支持当时判断。先把时间和结果的记录分开，避免把未来答案泄漏进过去。

- **先看文件：** `research/mining/prepare.py`、`temporal.py` 的现有筛选规则和 `tests/test_mining.py`，刘金彦在 `evaluation/` 写评测调用；算法问题交孙博文修改，源时间问题交李明洋协调。
- **输入与输出：** 输入固定截止时间、当时可得版本、原判断及随后确认的结果；输出发现时间、漏报、误报、判断改变原因和评价范围。仅做预测概率时才使用适合概率预测的评分，不凭空给材料打置信分。
- **错误例与验收：** 今天采用的旧文不能自动算作当年可见；后来的撤回、身份更正、人工标签不能提前给过去的算法。时间未知的材料不进入严格历史结果，另做当前资料评价。
- **依赖与进阶：** 李4先给可靠时间与版本，研究人员确定什么算最终结果。现有纯核支持部分时间约束，不等于真实历史评测集已经具备；资料不足时先做从今天开始留档的前瞻评测。

### 刘5：把复杂专题保持成清楚的交付

目标是支持中央、地方、学校和企业的实际讨论，同时让读者看清哪些是事实、哪些是条件和取舍。先把现有方案比较和调查记录展示准确，再增加表达。

- **先看文件：** `apps/web/src/pages/DecisionPage.vue`、`components/engine/DecisionResults.vue`、`api/decisionLabels.ts`、已有调查组件及 `delivery/`；沿用 `scripts/check_engine_ui_races.cjs`、`check_decision_ui_races.cjs` 检查相关迟到响应。
- **输入与输出：** 输入孙博文的比较结果与研究人员采用的判断，输出“要决定什么、为何现在、包括现状的几个选项、成本与受影响群体、哪些不确定会改结论、先做什么、何时复查”。用途标签只解释委托目的，不调整事实或权限。
- **错误例与验收：** 限额导致未计算时不展示空结果装成已比较；只有一个可比方案时不把后悔值为零解释为无风险；未接通的检索与专业核验不能显示绿色完成。请读者复述结论依据与限制，再改真正影响理解的地方。
- **依赖与进阶：** 孙博文提供正确结果，李明洋接来源与许可，专业人员确认业务解释。图表和导出按需要增加，不以页面数量代替研究能力。

## 依赖怎样排

先完成李1、孙1、刘1，三人能讲清已有例子；本轮提供的真实有界调查是共同起点。李2、孙2、刘2分别补新来源、一个真实策略缺口和面向读者的展示，不重复实现这个起点。随后推进李3、孙3、刘3，把 WeKnora 补查、异议和人工评测接上。版本、持续监测与历史评价按李4、孙5、刘4衔接；李5贯穿交付，孙4与刘5在有真实委托目标和数值时推进。

跨模块只交接需要的信息：孙博文提交一个具体待查问题及采用条件，李明洋返回实际材料和执行状态，刘金彦展示和导出；研究结果由孙博文解释。发现错字段或来源缺失，回到维护它的人修，不在三个地方各打一个补丁。每次交付留一个可运行例子、相关正常与错误检查，以及仍缺什么的短说明。

## 顶级情报能力还要补哪些内容

一次限定范围的调查只是起点。下面保留完整方向，但不把它们都算成当前 11 类方法已经完成。是否有用最终由真实决策、专业审阅和独立评测检验。

| 研究方向 | 当前能复用的部分 | 继续开发必须取得的条件 |
|---|---|---|
| 疾病负担、未满足需求与公平可及 | 区域指标同口径比较、调查问题与方案约束 | 有分母、人群、地域和时期的负担/服务资料；公共卫生与公平评价，不用文献数替代需求 |
| 科学证据与异议 | 文本线索、状态与反证线索、材料及判断历史 | 同研究与组别识别，效应、终点和偏倚资料，汪鑫怡的评价及专业复核 |
| 管线、产业链与供应韧性 | 有条件的管线格局、事件与关系路径 | 正确项目身份、前后版本、制造与实际供应资料；唐蔚雯提供有源关系，不把相关路径当因果 |
| 经济、支付与市场 | 现有数值条件、差异与情景比较 | 实际价格口径、支付范围、成本与财政资料、市场条件；专业模型与假设，商业收益和公共价值分别表达 |
| 人才、平台与成果转化 | 合作关系假说、阶段停留与调查记录 | 授权人员投入、设备排期、预算和能力，不用论文与节点数量推实际可执行性 |
| 监管与知识产权 | 状态、事件及待核问题 | 原始审评与安全材料、法域与有效期、权利要求和法律事件；法律与监管人员评价 |
| 政策工具、执行与效果 | 问题、方案、复查计划和记录 | 明确干预对象、执行过程、可比较结果和因果识别；当前没有自动政策效果模型 |
| 方案、预算、情景与长期复查 | 当前方案比较、保留历史的人工判断 | 委托目标、责任与资源，可靠变化来源；尚需持续跟踪和真实结果评测，不自动替人批准 |

同一份事实给不同客户看时保持原样。客户目标、价值取舍、资助与利益关系另外写明；资料访问按实际授权，不因客户职位或用途标签自动放宽。公开事实、单位授权能力资料和企业敏感资料不能混成一个可任意导出的资料池。

## 设计依据

以下用于约束开发方向，不证明本项目已经达到这些机构的专业水平：

1. [WHO EVIPNet](https://www.who.int/initiatives/evidence-informed-policy-network/the-evipnet-approach)：先确定实际优先问题，再组织全球与本地证据，说明实施和财务条件，形成决策者能用的证据简报。
2. [OECD：战略情报与政策试验](https://www.oecd.org/en/publications/oecd-science-technology-and-innovation-outlook-2025_5fe57b90-en/full-report/tools-for-agility-actionable-strategic-intelligence-and-policy-experimentation_288971cb.html)：持续扫描寻找弱信号，结合可靠多源资料和专家判断；信号具有不确定性，不等于确定趋势。
3. [ODNI ICD 203 分析标准](https://www.dni.gov/files/documents/ICD/ICD-203.pdf)：区分事实、假设和判断，说明来源、不确定性、替代解释、反面材料以及判断为何改变；分析不随客户偏好扭曲。
4. [Cochrane：更新综述](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-iv)：先看问题是否仍重要，再评估新资料或新方法是否足以影响结论，计划更新并保留变化依据。
5. [Gao 等，ALCE，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.398/)：答案正确性与引用质量分别评价。能找到一段引文，不足以证明全文结论成立，更不能代替医学专业评价。
6. [IARPA ACE](https://www.iarpa.gov/index.php/research-programs/ace)：预测必须对真实后续结果做实证评价。雷达先把问题、时间与旧判断留好，具备条件后再评价预测效果。
