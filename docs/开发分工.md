# 开发分工

李明洋负责总集成。孙博文负责研究计算。刘金彦负责产品页面和评测工具。每个目录只有一个维护人；需要改别人的模块，先说清输入、输出和要解决的例子，由维护人修改。

这一轮已有可继续开发的代码，不需要三个人再讨论一套架构。先跑通仓库里的例子，随后各做一个完整任务。合并时一起看结果，不能只展示自己的函数能运行。

## 先把现在的链路看明白

1. 徐子雯的 Data-Fabric 取得原始资料，保存版本、清洗字段和出处。
2. 雷达按研究问题、来源清单和截止时间读取资料；原文清洗后就能开始，不等图谱全部完成。
3. 孙博文的程序筛线索、组织追加查找、形成待核问题。涉及对象身份时用唐蔚雯的结果，涉及专业证据时用汪鑫怡的结果。
4. 李明洋的接口保存本次实际采用的资料和结果。潘倩的核验以后检查具体表述，不替代雷达的调查组织。
5. 刘金彦的页面让人看到查过什么、漏了什么、依据是什么。历史研究保存原预测，后续结局另存一版评价。

新历史例子入口是 `scripts/history_e2e.py`。里面的项目明确是教学材料，用已知答案检查程序。真实公开资料另走三个来源的采集和调查，不把两者混为效果证明。

## 李明洋：来源接入、运行和总集成

维护 `api/`、`adapters/`、`data/`、`db/`、`ops/`、`contracts/`。研究目录由孙博文维护，页面由刘金彦维护；总负责人不是替两个人写完各自模块。

### 第一个任务：接手这一轮联调

先读 `adapters/fabric_history.py`，沿“创建历史研究”走到 Fabric 的 `GET /api/history/records`，再看资料怎样进入雷达数据库。使用独立测试库运行一次演示历史研究和一次真实来源调查。

交付：能解释每个连接地址、凭据用途、数据库和后台进程；演示程序能重复运行；后来再读时仍返回当时采用的原依据，并核对当前来源许可。Fabric 暂不可用则明确提示，恢复后仍可读原版。上游故障、权限取消和超时必须在页面或返回结果中说清，不能显示空成功。

验收时给孙博文一份实际采用的资料，给刘金彦一个研究 ID。两人能直接接续，不需要你手工改数据库。

### 第二个任务：把变化持续送进雷达

已有 `/api/history/changes` 提供已提交版本的继续读取位置。做一个固定后台任务：读取一页、保存采用结果、成功后推进位置；中断再启动，从已确认位置继续。重复取得同一版本不重复发线索，失败页不推进。

这里只接已授权来源。删除、撤回、停止许可不是“这页没出现”，要等上游明确事件。先用两个受控版本和一次中页失败验证，再找真实修订案例。发布顺序、原件存储仍归徐子雯，雷达不另做采集数据库。

### 第三个任务：接上真正的取证服务

WeKnora 返回一次查找的范围、命中、版本和可定位原文，不能只给答案和链接。先完成成功、无结果、部分失败三个例子；孙博文据此决定下一步查什么。

唐蔚雯提供对象及谱系的历史映射。今日确认的别名不得回填成几年前已知。你负责传输、权限和调用，身份推断算法由唐蔚雯维护。

### 后续任务

把测试与迁移命令纳入持续检查；补单位账号、研究空间和来源权限；在有真实负载后处理索引、批量读取、后台恢复。共享服务和雷达分别保留仓库，不把所有项目合成大仓库。版本更新用正常 Git 提交；本轮临时联调分支审完后只保留一条主线。

## 孙博文：调查与挖掘

维护 `research/mining/`、`research/history/`、`research/investigations/`、`research/decision/`、`research/engine/`。外部请求通过李明洋的 adapter，纯计算里不联网、不读取当前时钟。

### 第一个任务：解释一次计算，再增加一个失败案例

先读 `history/compute.py` 和 `tests/test_history.py`。解释教学例子为什么给出 0.5、哪些旧项目没进训练、哪些项目不能评分。新增一个有业务含义的案例，例如同一项目出现相反结局，程序应保留冲突而非选自己喜欢的一条。

当前算法是分阶段历史事件率，样本少时退回总体历史率。它是可核对的比较基准，不是成熟的药物成功预测模型。不要把登记终止、监管缺陷、疗效失败或永久失败合并成一个标签。

### 第二个任务：把追加查找做得有用

当前追加词来自已取得资料中的真实标识，最多两次。挑一个实际专题，例如某类技术在某疾病上的管线变化，记录首轮缺什么、为什么继续查、查后是否补到关键材料。

你修改“选择下一问题、停止条件、采用结果的含义”；李明洋修改外部读取。结果至少区分支持材料、反面材料、未知、重复和补录。分类尚无专业依据时保留为上下文，不自动写成专家结论。

验收看三件事：追加查找确实取得相关新材料；没找到时保留问题；同样资料和预算下比原始单轮检索减少至少一种可核实的遗漏。效果数量由实际评测给出，不先定一个漂亮准确率。

### 第三个任务：从被动查找走向主动发现

复用现有 11 类方法，先选两类做实：项目状态变化与技术—疾病组合。为每类写清计算单位、时间范围、重复合并办法、比较基数和触发阈值。

先便宜地批量计算候选，再把有限调查预算给重要候选。按事件时间和公开时间分别看变化，排除一次补录、重复转载、采集量变化；没有可靠分母时，只能称候选，不能称趋势显著。新证据要能关联到已有调查，不能每天重发同一条。

### 第四个任务：用真实历史资料比较算法

拿到历史档案后，先定义预测对象、具体结局、12或24个月窗口和每个时点的完整队列。包括终止、未成功和至今未决项目。药物谱系不能跨训练和评价两边；试验登记号独立不等于药物独立。

保留本轮历史事件率作比较基准。再根据资料条件增加时间到事件、竞争风险或其他模型；比较同样的样本和截止时间，记录校准、漏报、审阅预算内命中及覆盖。缺标签不是负例，尚未走完窗口不进入固定窗口评分。

历史期间使用现代模型总结文字，只能称回顾性重建。要声称模型在当时可预测，还要核清模型和训练数据本身是否越过截止时间。

### 后续任务

接汪鑫怡的机制证据评价和潘倩的结论核验；把专业结果与事实、推测分开保存。政策、区域、学校和企业任务可以有不同目标及约束，但不因委托方不同改变来源事实。需要资源比较时接现有 decision，不能用文献数量代替预算、疾病负担、市场或执行能力。

## 刘金彦：页面、导出和独立评价工具

维护 `apps/web/`、`delivery/`、`evaluation/`，并维护跨服务演示脚本 `scripts/history_e2e.py` 和 `scripts/graph_e2e.py`。这些都是代码任务，不是只写报告或做人工测试。

### 第一个任务：让一个研究人员独立看懂结果

从历史研究页进入一项记录，逐项检查问题、截止时间、资料范围、候选、概率依据、采用原文和评价版本。把关键状态翻译成中文：部分完成为什么部分、未知缺什么、演示数据为什么不能当真实效果。

代码入口在 `apps/web/src/pages/` 与对应 API 类型。页面只展示服务返回的内容，不在浏览器另算概率或默默换统计口径。

验收：请一位没有参与开发的同学回答“用了多少资料、没看见什么、这个数从哪来”。他需要反复问开发者，页面就还没做好。

### 第二个任务：做能交给研究人员核对的导出

完善现有导出，让读者离开网页也能看到研究范围、计算口径、结论限制、重要原文和每版评价。优先使用保存过的资料；来源暂时断开不丢失本次采用依据；但当前许可无法核实时，原文与含原文导出暂停读取，恢复后读原版。

给引用编号，原文片段对应具体版本。不要把哈希串铺满报告首页。教学、程序整理、研究人员判断、专业审核状态分别明确。切换研究、退出登录或请求晚到时，不能把上一项研究的内容放进当前导出。

### 第三个任务：建一个能抓错的评测工具

你写样本导入、匿名编号、评分表、结果汇总和对比页面。导师或独立研究人员给专业标准，孙博文给算法输出；你不凭算法结果反过来编答案。

同一问题、资料截止和审阅预算下比较普通问答、知识库和雷达。记录事实错误、引用不支持、重要反例遗漏、重复线索、实际用时；还要抽查没被选中的材料，否则测不出漏报。专业标注与开发调参样本分开。

### 第四个任务：把历史评价展示完整

页面同时显示预测当时的证据和后来公开的结局；新评价另列版本。增加按年份、阶段、疾病和来源覆盖分组的视图，但小样本必须显示数量，不能只画一个“准确率”。

验收使用四种项目：有事件、明确无事件、窗口未成熟、资料不足。截点推进后状态可以变化，过去保存的预测和评分不能悄悄重算。

三人先一起运行 `scripts/graph_e2e.py`，读同一项真实调查。随后按以下边界修改，不能三个人同时改一套调查服务。

| 维护人 | 这次接手的代码 | 下一项交付 | 怎样验收 |
|---|---|---|---|
| 李明洋 | `adapters/fabric_graph.py`、来源许可与配置 | 和徐子雯、唐蔚雯接好连续发布：同一对象新关系有新版，原文可读，撤源与失败如实返回；只做调用，不做消歧 | 同一真实文档更新两次，旧版仍可读；中断后不重复采用；普通文本入口仍能用 |
| 孙博文 | `research/investigations/graph.py` 及对应研究接口 | 改进下一问题的选择：优先补能改变判断的缺口，明确查支持、查反例或核身份的目的；关系含义不匹配时不强塞现有算法 | 给出一项真实专题的逐轮记录；重复边不重复算证据；新关系触发复查，旧判断不改写；与同预算单轮查找比较遗漏 |
| 刘金彦 | `GraphInvestigationForm.vue`、调查阅读与 `scripts/graph_e2e.py` | 把图谱问题、查找词、真实命中、采用原文与缺口串成可读过程，补重名选择、切换调查和失败恢复的页面检查 | 非开发同学能从问题点到依据；自动审核、背景和已核资料显示清楚；晚到请求不追加到另一调查 |

唐蔚雯需要补的是源端能力：审核通过的真实关系、可靠的对象映射、按来源可追溯的别名、关系时间、合并记录和历史图快照。徐子雯负责原件及版本发布。雷达继续负责问题、调查预算、继续或停止、变化比较与判断更新，不把这些推回子课题。

当前真数据没有人工审核通过的关系，第一份验收材料应是一个小而完整的真实专题：由源端核实对象和至少一条关系，绑定确实支持它的原文；雷达读取并提出问题，查到补充或反面材料，交研究人员判断。数量不设成效果指标，空关系或合成例子不能替代这份材料。

## 怎么排顺序

第一轮三人并行：李明洋跑接入和异常，孙博文核计算和追查，刘金彦改阅读和演示工具。以同一个研究 ID 会合，端到端程序重新通过再合并。

第二轮：徐子雯交连续版本，李明洋接变化；孙博文做两类主动线索；刘金彦完成可审阅导出和第一批独立评价。先把一个专题做到可用，再扩大范围。

长期目标是持续感知、发现重要变化、调查取证、保存判断及检验效果。宏大的数据目录或复杂技术名词不能替代这一条链路的实际结果。
