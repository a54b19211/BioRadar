# 接口说明

运行中的 `/openapi.json` 和 `contracts/bioradar-engine.openapi.json` 列出实际接口。`bioradar-core.openapi.json` 保留完整产品目标，不能据此认为 `/api/v1` 已经可用。雷达研究功能使用 `/api/engine` 下的开发预览接口；下表雷达请求均省略这个共同前缀。

## 使用方式

浏览器先登录本地研究空间，后续用会话访问；命令行使用本地用户凭据。来源许可由服务器配置，页面不能自行增加权限。上游API key只在服务端使用。

写请求带 `Idempotency-Key`。同一次提交因网络原因重试时沿用原键；改变内容使用新键。修改调查时同时提交当前revision，旧页面的数据不能直接盖掉新记录。

## 后台持续计算

以下接口仍使用本地研究空间和当前来源许可，均在 `/api/engine` 下：

| 请求 | 用途 |
|---|---|
| GET /monitor/status | 是否启用、是否暂停、进程心跳、各源处理位置、发布端积压与资源状态 |
| GET /monitor/batches?limit=20&cursor=... | 固定批次、运行记录、实际版本数、使用窗口、阻塞原因 |
| GET /monitor/leads?limit=20&cursor=... | 候选、调查链接、延期原因及待补资料 |
| POST /monitor/control | 提交 `expected_revision` 和 `paused`，暂停或继续后台读取 |

控制写入需要原有凭据、Origin 检查和 `Idempotency-Key`。控制版本只随人工控制改变，不随心跳改变。进程配置启用不等于当前在线，以最近心跳和实际状态为准。

批次和线索读取会核对其所依赖的全部来源，不能只核对触发来源。已撤权项目不返回 ID 或正文；未能核对权限不是空结果。一个来源失联不阻止其他可读来源继续工作。

Fabric 的 `GET /api/history/publication/status` 返回源端发布心跳、待办数、补录位置和磁盘暂停状态，不返回数据库凭据。`GET /api/history/source-health?source_id=...` 另行区分原采集日志、发布、补录和固定查询。原库保存成功、版本发布成功、雷达已读取是三个阶段；发布在线不能替原采集报健康，旧页面兼容正文也不能替代固定版本回执。健康信息未知或读取失败不能写成没有新资料。`GET /api/history/changes` 的原游标规则保留，新增 `current_version_ids` 说明该页原记录在固定读取范围中的当前版本；补入旧档案不能把当前版倒退。

原库资料通过 `datafabric.collected.document.v1` 发布，保留原文、校验值、字段定位及明确的 active/withdrawn。临床协议直接复用来源侧字段解析，不把 JSON 键当正文主题。登记号只说明登记身份，不代表药物项目已经对齐。

自动材料携带服务器生成的 `payload.automation`，页面显示“程序整理，待人工核对”。普通 HTTP 追加请求不能自带该字段冒充后台；旧人工记录不追改作者。新版本和撤回事件能给原调查追加复查说明，但不会自动改写研究人员判断。

## 已有资料和计算

| 请求 | 用途 |
|---|---|
| POST /snapshots | 采用一份有来源的资料包 |
| GET /snapshots；GET /snapshots/{id} | 查看已采用资料及其本次内容 |
| POST /runs；GET /runs/{id} | 提交并查看线索计算 |
| POST /runs/{id}/feedback | 保存人工对线索的意见，不改原计算 |
| POST /decision-runs；GET /decision-runs/{id} | 提交并查看按给定条件的方案比较 |

资料、计算与调查列表遇到已撤权或暂不能核对许可的来源，跳过该项并返回 unavailable_count 和 availability_note，保留继续分页位置；不返回受限条目的 ID 或正文。单条读取仍返回 403 或 503，不用空结果掩盖失败。

资料格式见 engine-snapshot.schema.json，计算条件见 engine-policy.schema.json；方案比较见 decision-input.schema.json 和 decision-policy.schema.json。示例在contracts/examples。旧结果保留原输入、计算版本和依据；不拿今天默认值改旧结果。

## 固定原文与两种质量结果

WeKnora 返回的是候选。候选带有原记录编号和版本时，雷达回 Fabric 读取该固定版本；明确的版本不符不能改用当前版本补过检查。部分旧知识库仅保留来源站点和完整原始网址，雷达只在本次已经采用的材料中寻找唯一对应项，再回读原版本核对。没有对应项仍保留候选，不把检索片段直接放入证据。

这条旧库兼容路径记录 `binding_reason=selected_original_by_url`，同时保留 `search_version_verified=false`：它确认了可读取的固定原件，但未证明旧检索片段属于哪个版本。来源、原件版本、原文哈希和查询回执各自保留；标题相似不作身份依据。

报告的 `report.final_text` 是页面、数据库和 Markdown 导出的正文。`report.status`、`report.verification` 保存全文核验的原结果。`report.support_audit` 单独保存对所选支持片段的复核、目标范围及正文和证据版本。局部复核通过不等于全文已通过；REVIEW 表示所选片段待核，NOT_RUN 说明没有执行。旧报告未保存这一项时，页面照实显示，不补成通过。

JSON 导出包含两份质量结果，Markdown 保持原正文不变。正文核验回执出错、可选步骤预算不足、实际请求结果未知分别保存，不能都写成“没有问题”。

## 调查记录

调查记录同步保存在同一数据库；它不新增一种后台计算任务。入口可以是已有线索，也可以是研究人员直接提出的问题。

| 请求 | 用途 |
|---|---|
| POST /investigations | 建立调查 |
| GET /investigations | 列表 |
| GET /investigations/{id} | 查看当前问题、材料、判断和历史 |
| POST /investigations/{id}/entries | 追加材料、笔记、判断或进度变化 |

创建字段：title、question、questions、is_demo，以及可选origin。origin绑定实际run_id、result_hash、candidate_key，由服务器确认候选，页面不重新提交一份候选正文。is_demo只是教学标记，false不能自证资料真实性或扩大来源许可；采用范围由服务器核对。

追加内容分四种，均携带expected_revision：

- note：text，保存研究笔记。
- material：snapshot_id、record_ref、quote、stance、text。stance为support/oppose/context/uncertain，是研究人员对本问题的分类，不是专业评价结果。
- judgment：text、conditions、basis_entry_ids、assessment。依据只用本调查已加入的材料ID；assessment为provisional或unable_to_determine，不能提交“专业已批准”。
- status：status、text、question_updates。状态为open/paused/closed；关闭表示停止跟进。question_updates指定已有问题及pending/checking/resolved/blocked状态。

服务器保存提交账号、时间、当时依据和上一版判断；目前使用本地开发账号，尚未接学校统一身份。只要存在未纳入最新判断的材料，needs_review就保留复查提示，旧判断及其依据不改变。机器核验与研究人员审核分开记录。BioCheck 的 PASS 不代替人工批准；未经研究人员审核，professional_status 仍为 not_reviewed。

判断写得是否正确由专业审阅确认；程序负责不丢依据、不串记录、保留变化。自动查找与字段整理保存为明确标注的note和context/uncertain材料，不自动提交研究人员judgment。

## 机器分析

页面和后台共用这些实际接口：

| 操作 | 接口 |
|---|---|
| 可选来源、预算上限和上游状态 | `GET /api/engine/investigations/research-options` |
| 输入问题并立即开始研究 | `POST /api/engine/investigations/ask` |
| 已有调查开展分析或追问 | `POST /api/engine/investigations/{id}/analyses` |
| 读取本次进度和结果 | `GET /api/engine/investigations/{id}/analyses/{analysis_id}` |
| 导出同一结果 | 上述分析路径加 `/export`；`?format=markdown` 返回保存的报告正文 |

首问正文至少包含 `question`，可选 `source_ids`、`budget` 和明确的 `initial_queries`。不传初始查询时由系统提出。响应含 `investigation_id`、`analysis_id`；前端据此持续读进度。首问创建调查后若启动失败，会返回已经创建的调查身份，页面可以继续打开它。

追问包含当前 `expected_revision`、新的 `question`、`parent_analysis_id` 和 `auto_retrieve:true`。问题属于本轮分析，后台刷新和后续材料不能改写它。原先只对已采用材料开展分析的调用方式仍可使用。

待核、失败或阻塞的分析可显式提交 `retry_of_analysis_id`，另建一次尝试。省略 `question` 和 `parent_analysis_id` 时沿用被重试版本的值，包括原父版为空的情况；来源和预算按本次请求及服务器上限核对。网页“重新研究”传入旧版显示的问题、父版、来源和预算，携带幂等键。刷新页面不发起重试，原失败稿及调用记录保留。

`budget` 可设置 `max_calls`、`max_tokens`、`max_seconds`、`max_queries`，取值不得超过服务器上限。返回的 `budget.limits` 是本次上限，`budget.usage` 是实际用量、保守计数及未知项；各专业方法使用同一执行回调。

`queries` 保存来源、阶段、查找词、实际结果和失败原因。`evidence` 保存真正采用的原件；WeKnora 候选没有绑定原件前不进入此列表。`calls` 保存模型请求的阶段及回执，`progress` 显示当前执行阶段。

最终交付文字位于 `result.report.final_text`，其核验状态是 `result.report.status`。它与前期结构化分析分开：最终正文通过，不会把旧命题逐条标为已通过。`result.mechanism_evaluation` 保存 MechEvidence 的实际评价、输入范围与缺项；不是人工批准。来源许可仍在读取时核对。

Markdown 导出使用同一保存正文，JSON 导出包括分析和来源结构。追问保存新版，原版与原件继续可读。

## 逐步查询与质量反馈

提问与开始分析请求增加可选 `query_policy`，值为 `baseline` 或 `query_planner`；不填采用服务器配置。该选择、源码版本、选择方法、停止方法与训练状态固定到本次分析，恢复沿原决定执行。

`AnalysisView.query_policy` 和最终结果保存决策列表：候选动作、预计覆盖项、所选动作、实际回执、采用的证据、后续决定及停止原因。工具未知费用保持未知。整项调查共享模型调用、token、查询次数、工具请求次数和时限。

`complete` 指声明的取证覆盖检查有当前原件支撑，不表示科学结论正确或人工批准。`insufficient` 保留未查范围。论文数量、图关系数量和独立研究数量分别记录。

BioCheck 的 `quality_feedback` 给出材料缺口与允许修改的单元，模型请求走雷达统一回调。原文错误、核验器回执错误、片段选择错误分别处理。修改后重新核验全文；报告、页面、JSON 和 Markdown 使用同一最终正文。

人工材料的立场和待核备注保存在 `material_context`，图背景通过 `evidence_role=graph_background` 标明。它们与原文分开传递，并计入本轮输入身份；用户备注不会被当成已经证实的事实。最终核验接收固定的 `assessment.research_scope`，包含已查范围、未解决问题和来源失败；MechEvidence 的片段编号附固定原文位置映射，不能与雷达片段编号直接混用。

历史语义入口：`POST /api/engine/history/studies/{id}/analyses`，请求可含 `query_policy` 和 `budget`，携带 `Idempotency-Key`。它采用该研究保存的特征资料与截止时间，返回普通 `AnalysisView`；`HistoryStudyView.semantic_analyses` 列出对应分析。原预测和后来评分独立保留，结局资料不进入语义调查输入。

图查询通过 `adapters/query_graph.py` 调用 Fabric 名称查询、关系采集与固定版本读取。身份候选、图背景和已绑定研究原文分别存储；历史调查禁止查询当前图后冒充过去状态。

## 有界真实查找

下面的旧 Data-Fabric 研究接口最初在 `9ab8bd4` 引入，10 月 16 日完成真实读取、保存与回读验收。现役 Fabric `dev` 已包含截至 `4e7fb67` 的后续业务改动；`f493b05` 补了修改报告。该旧入口仍只读已有临床登记，不启动采集、抽取、图谱合并或模型任务。

| Data-Fabric 请求 | 返回内容及边界 |
|---|---|
| GET /api/research/documents/search?terms=BCMA&terms=myeloma&limit=6 | 标题按原样词语做 AND 查找；有当前条件、来源、实际命中项和是否还有更多，不是全文或完整专题检索 |
| GET /api/research/documents/{uuid} | 已保存协议的原样片段、原字符定位、原内容标识和字段路径；无法投影时明确返回原因 |

上游源码入口为 `api/routers/research.py` 与 `biz_rules/clinical_research.py`；雷达读取入口为 `services/bioradar/adapters/data_fabric_research.py`，以 `search`、`read_document`、`snapshot_from_documents` 使用。`research/investigations/digging.py` 中的纯函数 `select_followups` 根据实际干预名选择下一查询，`summarize_trials` 比较登记字段，实际调用与保存由现有调查服务完成。

一次限定最多三轮，每轮最多六条候选，采用材料不超过十八条。保存每轮条件、触发的原字段、复用记录、上限、空命中和失败，不能把失败改为空成功。协议 JSON 用于有出处的结构事实，不作为清洗正文挖出 JSON 键主题；登记停止状态与来源所述停止理由不代表疗效、安全性或战略价值的专业结论。结果可得性未提供时保持未知。

采用包的版本表示本次读取的固定内容，上游仍是当前记录读取；这个旧接口不承担不可变历史版本；持续链路使用新历史接口和源端发布程序。WeKnora 取证、机制评价和表述核验仍各自按实际连接状态说明，不能因这条链路成功就一起标成已接通。

调查视图包含只读 `data_fabric_retrieval=bounded_cli_available`，表示具备这个有界命令入口，不表示某调查已经查过资料。原 `retrieval_status` 是旧入口保留的兼容字段；本次 WeKnora 是否配置、是否执行以及读到什么，以研究选项的 `providers` 和具体分析的查询回执为准。

命令入口、参数文件与输出见[开发说明](开发说明.md)。它在宿主机直接调用本项目已有 PostgreSQL 保存逻辑，无须启动雷达 HTTP API 或 Worker；外部访问仅经过 adapter 的两个 GET。程序把事实与待核事项写成笔记和材料，不增加后台计算类型或调查表。

## 历史资料与新来源

已接通的 Data-Fabric 历史接口与旧 `/api/research` 并存。新来源走这套接口，不通过更换旧临床查询词冒充接入。采集和导入由 Fabric 管理员发起，雷达只有只读许可，不直接访问其数据库。历史详情、原件和导出读取前仍核对 Fabric 当前来源许可；撤源拒绝读取，上游暂不可用则明确返回不可用。保存副本不代表永久授权。

| Data-Fabric 请求 | 用途 |
|---|---|
| GET /api/history/sources | 来源及十类业务目录；已接入与计划分开 |
| POST /api/history/fetch | 受理限定公开抓取，保存任务后送现有 RQ |
| GET /api/history/runs/{id} | 实际范围、状态、次数、采用版本和失败原因 |
| POST /api/history/runs/{id}/retry | 核实原任务已失活后重试；必须带 expected_attempt |
| POST /api/history/archives | 导入有明确范围的档案包；历史证明和映射审核分开 |
| GET /api/history/records | 按来源、演示标记、截止时间和清单读取；分页冻结上限 |
| GET /api/history/versions/{version_id}；其 /raw | 读指定采用版本和原始内容 |
| GET /api/history/changes | 从已确认位置继续取得本系统发布的版本变化 |

新接口凭据为 `DATAFABRIC_HISTORY_READ_TOKEN` 与 `DATAFABRIC_HISTORY_ADMIN_TOKEN`，雷达只拿前者。archives/fetch 写请求带 `Idempotency-Key`；同键改内容返回冲突，不能用重试覆写原任务。

读取参数包括 `source_id`、`is_demo`、`mode`、`cutoff`，可带 `run_id`、原记录 ID、词语或记录类型。每页最多 100 条，续页沿用同一条件与 cursor。run_id 固定当次声明的成员清单，再在截止时间前的合格版本中选最新版；不是永远读当前正文。

`coverage.complete` 只对声明清单有效。任意关键词命中、第一页读完、达到数量上限，都不能解释成整个来源或领域完整。缺少当时可见的成员会记录缺口。变化接口表示本系统采用的版本，不等于原站所有事件；本批未出现不代表删除。

每条资料保留来源 ID、原记录 ID、版本、原始内容、清洗正文、字段定位、解析版本、日期和取得记录。原始 JSON 定位不能冒充 PDF 页码。首次取得由服务器写入；客户端不能伪造过去的 first_seen。档案审核证明必须覆盖本次采用的原件，不能凭一个旧发表日期把更新后的正文倒填回过去。

三种 mode：

- `current`：当前资料研究。
- `operational_replay`：截止前系统实际收到的资料。
- `public_history_reconstruction`：有审核档案证明的当时公开版本。

公开抓取本身不产生历史审核资格。历史档案入口可以接以后取得的合法快照，现在不声称有完整十年资料。接口存在也不等于已启用常驻采集：现役固定刷新仅 WHO 与 Europe PMC 的限定查询；ClinicalTrials 的持续续页、PubMed 的现役历史许可和 FDA CRL 的常驻接入分别仍有缺口，具体范围见资产盘点。

## 图谱引导调查

Fabric 新增两条只读接口，均指向一个固定版本：

| 请求 | 返回什么 |
|---|---|
| GET /api/history/graph/{version_id}/resolve | 按名称、已许可别名或外部 ID 返回候选；多个候选不自动取第一个 |
| GET /api/history/graph/{version_id}/neighborhood | 指定种子、关系类型和方向，返回限定邻域及实际读取范围 |

两者都带 `source_id`、`source_record_id`、`is_demo`、`mode`、`cutoff`。resolve 带 `name` 或一对 `external_namespace/external_id`；neighborhood 的 `seed_ids` 为重复参数，值是 `namespace|id`。邻域最多两层，范围是所发布资料包，不能称扫描完整 PrimeKG。方向保持源关系声明的方向，不能把反向遍历解释成反向因果。

雷达接口仍省略 `/api/engine`：

| 请求 | 用途 |
|---|---|
| GET /graph/packages?source_id=primekg_graph&is_demo=false | 列出当前允许读取的图资料，供页面选择；续页把 as_of 作为 cutoff、next_cursor 作为 cursor 原样传回 |
| POST /investigations/graph | 新建或追加一次图谱调查，返回实际查询、材料、缺口和调查 ID |

请求固定 `source_id/source_record_id/graph_version_id/is_demo`，填写 `title/question`；`seed_names` 与 `seed_ids` 二选一。可选 `topic_terms` 限定主题，`compare_version_id` 比较前一图版本；追加已有调查时必须同时带 `investigation_id/expected_revision`。当前最多回读四份图绑定原件，另做两次临床标题查找、每次最多三条，达到范围就注明，不能自行放宽条件求命中。

首次提交带幂等键。操作已经开始后重复请求返回 409，按已有调查和回执核对，不自动再次执行外部查找。名称歧义返回 `awaiting_seed_selection` 和候选。结果中的 `partial/read_failed/empty_neighborhood` 分别表示部分完成、读取失败和所选邻域为空；保存调查不等于取得有效证据。

`contracts/graph-bundle.schema.json` 与 `graph-request.schema.json` 对应实际交换字段。对象带命名空间、身份和审核状态；关系带方向、时间含义、证据版本、原文和字符范围。文档引用精确绑定原始版本，未知时间不取文档发表日代替。确认身份、原文确实包含这句话、这句话是否证明机制，是三个不同问题。

交换结构支持审核出处与合并记录，但源端旧图转换尚未完整传出审核人和时间，HTTP 捕获与自动发布中的 `merge_logs` 目前为空。自动发布要求引文在目标清洗正文中唯一匹配，旧图 CLI 捕获仍取首次匹配；雷达的精确切片检查不证明重复句定位和专业含义均正确。原文位置与清洗正文位置分别使用，不能互换。

撤审或撤销字典确认会形成资格改变的新版图，原图和原调查依据保留，后续计算按新版资格判断；来源撤权则使旧采用记录也须按当前来源许可拒读。图待办可归并多个中间审核变化，当前图版本不等于完整逐次审核日志。

当前图和旧文档桥接只保存这次观测。首次收到之后可用 operational_replay 回看当时已收到的版本；仍不具备 public_history_reconstruction 所需的外部历史档案证明，也不能用于收到之前的时点。PrimeKG 始终是背景；自动审核关系、未绑定原文或未确认对象不会被悄悄升级为已核实证据。图资料的来源许可与所依赖原始来源共同检查，撤销原来源后，已保存调查也不能绕过去读取。当前按来源组保守限制，尚未实现单位、多租户的细粒度许可。

## 长期专题与固定观察

以下接口位于 `/api/engine/topics`，仍用现有会话、来源许可与写请求幂等键。

| 请求 | 用途 |
|---|---|
| GET /templates | 读取四个起步模板及输入限制；不是四类数据均已接齐 |
| GET /；POST / | 列出或创建专题 |
| GET /{id}；PUT /{id} | 读取专题，或保存新的研究范围；旧范围不覆盖 |
| POST /{id}/control | 按 `expected_revision` 暂停或继续 |
| GET /{id}/evaluations | 按形成时间读取历次观察 |
| GET /{id}/evaluations/{evaluation_id} | 读取某版固定问题、依据、计算和草稿 |
| GET /{id}/evaluations/{evaluation_id}/evidence/{key} | 按本版证据索引回读原件，仍检查当前许可 |
| GET /{id}/evaluations/{evaluation_id}/export | 下载本版 JSON 研究记录，不自动批准发布 |

`definition` 包含研究问题、用途方向、来源、站点和词项范围、观察方法、周/月周期及复查间隔。`domain` 只作整理标签；实际可计算的内容由 `profiles` 与输入字段决定。真实资料用 `datafabric-test` 来源实例，教学资料用 `fixture`，两者许可分别核对。

范围版本、采用贡献版本和计算版本分别保存。新专题及改范围从自己的起点补查，不借用全局 Monitor 的已处理位置。观察的 `definition` 是当时版本，不能拿当前标题解释旧结果。

`coverage` 区分完整采用数量、本次计算范围、未纳入部分、时间缺失、撤回及来源错误。处理完 Fabric 已提交版本不等于原站全量。`upstream_health` 将原采集记录、版本发布、库存补录和固定查询分开；没有检查记录时返回未知。

普通正文可以进入文字观察，登记字段进入状态比较。`datafabric.observation.v1` 通过已有 `external_archive/document` 入口接收数值或事件；它不是另一套图谱或实体对齐。`declared` 保留输入声明，`source_bound` 必须由 Fabric 核对完整原版本、字段位置、数值及口径。绑定成立不等于来源真实、研究独立或专业结论正确。

数值同系列仍需核对象、期间、单位、地区、人群和分母；重叠期间、未知口径、目标值和超出支持范围的输入不能混成增长曲线。明确的 `supersedes` 用于替换旧贡献，旧观察继续按当时采用版本回读。

## 历史研究与评分

以下仍省略雷达共同前缀 `/api/engine`。

| 请求 | 用途 |
|---|---|
| GET /history/sources | 当前许可范围内的来源目录 |
| POST /history/studies | 读取资料、限定追查、采用证据、保存调查与固定预测 |
| GET /history/studies；GET /history/studies/{id} | 研究列表和已保存结果 |
| POST /history/studies/{id}/evaluations | 在更晚截止时间读取结局，追加独立评分 |
| GET /history/studies/{id}/evaluations/{evaluation_id} | 读某一次评分 |
| GET /history/studies/{id}/evidence/{version_id} | 读本研究实际采用的原件；评分证据另带 evaluation_id |
| GET /history/studies/{id}/export | 导出已保存的研究记录 |

创建请求示意（run_id 换成真实导入回执，不能照抄占位值）：

~~~json
{
  "title": "一个预先确定的项目队列",
  "question": "按当时资料，未来12个月内的公开获批事件率怎样？",
  "source_id": "external_archive",
  "is_demo": true,
  "mode": "public_history_reconstruction",
  "cutoff": "2018-01-01T00:00:00Z",
  "target": "regulatory_approval",
  "horizon_months": 12,
  "run_id": "<2018年队列清单回执>",
  "training_runs": [
    {"cutoff": "2016-01-01T00:00:00Z", "run_id": "<2016年队列清单回执>"}
  ],
  "review_budget": 10,
  "followup_queries": 2
}
~~~

支持目标为 `trial_stoppage`、`regulatory_approval`、`next_phase_disclosure`，窗口为 12 或 24 个月。本版计算公开披露事件的历史频率，不等于药物疗效、项目永久成败或投资回报。项目级计算要求经核实且在截止前可见的身份、谱系、适应证及法域；仅有 NCT 号不能代替项目谱系。

`training_runs` 为每个历史时点指定自己的清单；旧 `training_cutoffs` 参数仍保留，但无声明范围时不能产生“全量训练”的假象。训练结局必须在预测截止前公开。预测项目与训练项目按可用谱系分开，旧终态项目可保留排除记录，不计当前风险集。

历史计算只给出分阶段事件率基准，样本不足时可退到总体基准并说明；无合格样本不给概率。资料、时间或预算不足时返回 partial/unsupported 等具体状态，不返回任意分数。

评分请求为 `{"cutoff":"2019-03-01T00:00:00Z"}`。新评分不改变预测，也不覆盖旧评分。窗口未成熟为 censored；缺少明确结局或完整阴性观察为 unknown；未知不补零。Brier、校准和审阅预算内命中同时报告样本数、覆盖及限制，不能只报一个“准确率”。本版同阶段项目可能得到相同事件率；并列按单位 ID 稳定排序，因此预算内命中只是这个预先固定排序下的描述结果，不证明模型会优先挑中成功项目。

研究读取有条数、字节和时间预算；每页 100 条不是研究总量上限。默认采用预算 5,000 条，受字节和时间预算共同限制。达到预算后说明范围，不能把残缺队列算成完整结果。

## 两次资料比较

GET /snapshot-comparisons?before_id=...&after_id=... 比较两份已经成功采用的资料。比较仅覆盖所选范围，不能据此宣称扫描过全库。

输出区分新增、内容改变、内容相同、本批未出现；来源属性或身份补充另行说明。记录身份取来源实例和原记录标识，不用新映射的疾病/靶点ID替换文献身份。读取失败在读取阶段返回错误，不伪装成空包参加比较。

## 引用和日期

record_ref由实际采用资料提供，保留provider、object_type、object_id、adopted_version、version_source、content_hash、authorization_ref。附材料时复制已有引用，不自行编造。同一调查的已采用来源不能混合真实资料与教学资料；直接提出的问题第一次采用教学材料后，整项调查明确标为教学。quote必须来自这一版本的实际文本；无文本的结构化记录仍要说明采用范围。

资料发生/公开日期、上游首次可见、本次观察时间各自保留。今天读到旧资料不等于今天有新进展。内容标识用于关联版本，不能证明专业结论正确。

## 方法范围

现有发现方法覆盖词组与文本主题、技术/疾病组合、状态变化、管线格局、合作网络、证据阶段变化、反证影响、阶段停留、事件影响路径及区域指标比较。各方法分别说明输入条件；正文可以开始探索，缺图谱或专业评价只影响依赖它的方法。

方案比较检查资源条件、相对现状差异、多目标取舍及声明情景下的损失范围。它不提供默认价值权重、成功概率或未经专业模型计算的政策效果。现有方法与未来研究目标分别列入项目说明和资产盘点。
