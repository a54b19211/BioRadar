### 先改哪些地方

**1. 重启不能清掉正在做的事。** 10 月 16 日已去掉 API 启动清队列、重置记录和管理对象初始化盲目重发的行为；完整的失活判定与恢复尚未实现。后续只恢复已确认失活的任务。任务先记入数据库，再送现有 RQ；投递中断可以查到并补送。领取和完成都要核对本次执行身份，旧 Worker 不得覆盖新任务。任务去重包含资料版本、处理阶段和解析/模型/规则版本；重试记为新的尝试，算法升级也能重新计算。

**2. 把失败和部分完成如实返回。** ClinicalTrials 翻页请求失败会直接结束迭代；重采时又存在忽略写库返回值、直接累计成功的路径。数据库未配置时，写入函数也可能返回后被上层记为成功。分别记录取得、保存、隔离、失败的数量，失败页不能推进完成进度。固定查询条件与时间范围，先保存已确认内容；分页令牌失效时从重叠范围重新读取并去重，不许诺依靠旧页码精确续传。配置里写了重试次数，还要确认实际执行入口真的会重试。

**3. 同一条资料更新后，要留下前后两个版本。** 网页采集入口会跳过已有 URL，所谓增量在遇到第一条旧记录时就停；API 写库则可能覆盖旧正文而沿用旧的“抽取完成、同步完成”状态。两条路径都要按来源稳定 ID 识别记录，内容变化产生新版本，派生结果绑定其输入版本。重采应先取得并保存新内容，再切换当前版；抓取失败不能先使旧实体和关系失效。

**4. 给雷达提供能持续读取的接口。** 现有文档列表按更新时间倒序翻页，详情只读当前 UUID 内容，适合页面浏览，不能保证增量不漏。补充“按记录和版本读取”与“从上次位置继续读取已发布变化”两种能力。变化要包括内容更新、撤回、删除和访问条件变化；本批没出现不等于删除。原文回读仍检查当前许可。

实现时沿用 PostgreSQL 的短发布事务，把版本和变更记录一起保存，发布顺序提交后才可推进。不要直接把 `updated_at`、页码或裸序列最大值当作安全进度；两个事务反序提交时也不能漏掉后提交的数据。可用现有数据库锁串行分配发布序号，无须增加 Kafka、CDC 或新工作流。

**5. 把字段含义写对。** 当前 ClinicalTrials 配置把最后更新日期映射到 `publish_date`，清洗器却把它写成“开始日期”。另有整数缺失、格式错误都被填成 0 的路径。分别保存首次公开、来源更新、事件发生、首次取得时间；临床试验的实际日期和预计日期也要区分。未知数值用空值及原因，真实的 0 保留为 0。既有历史记录的日期含义不清时标明未知，不静默重写。

按许可保留原始 JSON、PDF/HTML、清洗正文和原文定位，注明解析版本、日期精度、单位、人群和统计期间。当前通用 API 映射会把 summary 截到 500 字；摘要、正文和结构化结果分别声明覆盖范围。已有字段可直接解析，不让大模型重新猜一遍。回填处理记录不能自动写成“当时质量检查通过”。

**6. 下游接到并处理了什么，要逐项确认。** 图同步存在只看 HTTP 成功就把整批标为已推送的路径；文档同步存在请求一条、实际读取一批的路径。先固定本次允许处理的记录清单，按尝试数量限制范围；按目标知识库、来源 ID 和发送版本核对每条结果。区分确认成功、失败、尚未确认，超时或含义不明的冲突响应先查回执。发送期间本地内容更新，旧回执不能把新版标成已同步。

审核决策、业务写入和运行记录也要对应；不能写库失败却返回“已批准”。独立同步脚本与 API 共用数据库记录，不再用一份只记 UUID 的文本文件决定哪些内容已经同步。徐子雯负责资料发送和任务基础，唐蔚雯负责图谱审核、投影及撤回，李明洋确认 WeKnora 对端实际接收和回读的字段。

**7. 补齐共享服务的入口和运维。** 本轮应用代码未见服务身份依赖，网关和文件服务部署权限尚未核实，不能据此断言公网暴露。接入其他项目时给雷达只读账号，上传、重采、审核分开授权，来源身份由服务端绑定；人工上传不能靠填写一个官方站点名和 `confidence=1.0` 自证可信。附件返回可授权读取的标识，不向下游暴露本地路径。启动合并任务的 SSE GET 改为 POST 受理，GET 只读取已建立任务的进展。

限制单次上传大小、批量数量、并发和重试；健康检查分别反映进程、数据库及队列状况。每个来源能看到最近成功批次、实际查询范围、新增和修订数、失败原因、最长积压。把实际启动脚本、依赖版本和恢复操作纳入仓库，在隔离环境验证备份恢复。图谱写库时已有的预计算 embedding 要传到消费位置，避免持有全局写锁后再次联网计算。

### 已有来源先查清覆盖范围

当前默认配置中，ClinicalTrials 只查 `cancer`，每页 20 条、最多 10 页；PubMed 查 2024—2025 年的 `drug safety`，最多 200 条。这是当前入口的默认范围，不能据此反推历史库的来源或总覆盖量。

徐子雯先为已有来源列一张表：取得方式、检索条件、覆盖时间、是否到达分页末尾、最后成功批次、更新字段、停采原因和可使用范围。按任务读到页数上限就是有限样本，不能写成该站全量。先抽查已保存的原始资料能否补出缺少字段，再决定重新获取哪些资料。

### 接下来补哪些数据

通用建设先做前四类；中央和省级专题把需求、支付前置，高校专题把实际能力前置，企业专题把管线、审评风险、专利和财务前置。优先级随任务调整，事实口径保持一致。

取得方式和数据含义也要一起落实：

- **临床登记：** ClinicalTrials 有[官方 API 规范](https://clinicaltrials.gov/api/oas/v2)，按研究 ID 保留自己取得的各次版本。中国登记入口见[药物临床试验登记与信息公示平台](https://www.chinadrugtrials.org.cn/)；本轮没有验证其匿名批量 API。区分首次登记公开、最后更新、试验实际/预计日期、结果首次公开；未取得结果不能写成试验失败，终止原因也可能与疗效无关。
- **反面监管证据：** [FDA CRL](https://open.fda.gov/apis/transparency/completeresponseletters/) 提供当前申请存在的审评缺陷，可能后来补正获批，也存在档案补录；[EMA 下载资料](https://www.ema.europa.eu/en/medicines/download-medicine-data)包括审评、撤回和安全/供应信息。FDA 现有召回 API 的[官方说明](https://open.fda.gov/apis/drug/enforcement/)明确限制用它追踪召回生命周期或直接向公众发警报，不能用旧状态推断现在是否结束。
- **论文更新：** 用 [PubMed 更新文件](https://pubmed.ncbi.nlm.nih.gov/download/)或按专题更新读取，补更正、撤稿及关联原文。数据库删除不等于撤稿，同篇论文跨库出现不算独立研究。[Europe PMC](https://europepmc.org/developers)可补元数据与许可正文；[PMC 正文规则](https://pmc.ncbi.nlm.nih.gov/about/copyright/)指定自动取得渠道及许可要求，不能把有 PMCID 当作任意批量下载许可。
- **支付和需求：** [医保目录变化说明](https://www.nhsa.gov.cn/art/2026/1/7/art_14_19254.html)、[采购公告](https://www.ccgp.gov.cn/)及[医保公开统计](https://www.nhsa.gov.cn/art/2026/7/6/art_257_21309.html)可作为入口，先按专题取得表格和附件；本轮未验证这些站点通用批量 API。中选价不等于企业收入，约定采购量不等于患者需求，部分病种统计不补成其他病种为零。[WHO DON](https://www.who.int/emergencies/disease-outbreak-news)也不是全球所有事件的全量清单，没通报不等于没发生。
- **执行能力：** [NSFC 查询说明](https://www.nsfc.gov.cn/p1/2961/2962/3648/cx.html)区分公开成果与需要本人/单位核实的信息。实际人员投入、设备排期和预算余额主要靠单位授权资料，不能用论文数量代替。涉及咨询客户的资料按项目区分访问范围。
- **专利与企业：** 优先核实 [CNIPA 开放服务](https://ggfw.cnipa.gov.cn/)和 [EPO OPS](https://www.epo.org/en/searching-for-patents/data/web-services/ops)的注册、额度及数据条款；[Orange Book](https://www.fda.gov/drugs/drug-approvals-and-databases/orange-book-data-files)不覆盖全部生物技术权利，WIPO 批量产品另核许可和费用。专利登记不能自动推出自由实施结论。[HKEX 条款](https://www.hkex.com.hk/global/exchange/terms-of-use?sc_lang=en)限制自动提取和文本数据挖掘，现有爬虫配置不代表取得相应许可；先确认授权服务或企业提供材料的方式，再扩大来源。

### 第一轮交付看什么

先修启动清队列、失败误报成功和重采破坏旧记录，再选一个明确专题，用 ClinicalTrials 的结构化资料跑通下面的交接：

1. 取得一批范围明确的资料，保存原始内容和清洗结果；雷达能直接读取，无须等图谱抽取。
2. 再取得更新资料，能解释新增、内容修改和补录；同一研究的两次版本都能读回。
3. 找一条真实状态变化或公开反面材料，把原文、版本和日期交给雷达，建立调查。暂未找到真实变化时明确说明，开发用合成例子另作标记。
4. 在隔离环境检查运行中重启、第二页失败、重复提交、旧任务迟到、撤回和越权读取。没有丢失、误报成功或错误改写旧版后，再扩大采集范围。

随后补 FDA CRL 或 EMA 反面资料，并修正 PubMed 的持续检索范围。按专题逐步增加支付、需求、专利和实际能力数据。这是实施顺序，最终覆盖仍按研究院的任务扩充；每轮交付应说明现在能回答什么、仍缺什么。
