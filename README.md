# BioRadar 项目说明

BioRadar 接收 Data-Fabric 整理的资料，计算变化和候选线索，继续查找相关材料，保存调查过程与依据。它也接受研究人员主动提出的问题。

源码统一在 zktest 的 `/home/zk_test/zk_projects/BioRadar`，主线为 `main`。李明洋负责集成与运行，孙博文负责研究逻辑，刘金彦负责页面和评测。4022 不保留开发副本。

## 本轮验收状态

2026 年 10 月 19 日，zktest 主线已接入 DeepSeek，恢复持续读取和机器分析。Fabric 保存资料后，后台继续筛选、补查、形成草稿；研究人员仍须核查结论。15176 网页调试服务保持关闭。

本轮实际检查了两个问题：

| 问题 | 实际结果 |
|---|---|
| 一项临床登记终止，能否理解成安全性或疗效失败？ | 登记与公开论文完成解读、补查、一次修订和旧命题比较；有限范围内的内容及页面通过非作者审查。 |
| 几篇肿瘤研究是否属于同一主题？加入一篇 IL-7/TCE 论文后怎样更新？ | 正常添加材料即自动生成新版，补查还取得同一篇 ADC 论文的另一版本，未算成独立研究。两版均保留待核，当前稿未通过，因此没有执行旧版比较。 |

第二个问题暴露了真实错误：模型把实体瘤与其子类骨肉瘤当作互斥疾病，也混用了研究主题和同一项目。相同模型的复核没有抓住所有问题。故本轮交付范围是持续生成、有出处且可审阅的机器草稿，不能自动签发专业结论。此前 Qwen 的错误和 DeepSeek 首次截断记录全部保留；执行、限制与审查记录统一见 evaluation/handoff-verification.json。

## 现在怎样工作

徐子雯的程序保存新资料后，Fabric 在同一次数据库提交中记下待发布的变化。后台发布程序保存原文版本，雷达继续读取新版本、运行已有算法；符合条件的线索自动建立调查，补查相关材料并保存出处。没有新资料时不会反复计算全库。

这条链不要求先完成图谱。普通正文可以用于文本线索，临床登记的明确字段可以用于状态比较；唐蔚雯核实的对象、关系和时间资料到达后，再进入相应计算。PrimeKG 用作背景与查找方向，不能替代逐条研究证据。

后台把三件事分开：新取得了什么资料、什么值得调查、什么有依据判为紧急。旧资料补录不等于新近科研进展，登记终止不等于药物疗效失败，程序补查的材料也不自动成为支持证据或专家判断。

网页的“情报雷达”页可查看后台状态、已处理位置、候选和调查，也能暂停或继续自动读取。页面刷新只是读取状态；已有的手动分析、图谱调查和历史研究入口继续保留。

## 长期专题

“情报雷达”继续从新增资料里发现尚未指定方向的线索。“长期专题”持续记住一个明确问题：它采用过哪些资料，上一版看到什么，什么新证据需要继续查。两者使用同一套来源、调查和权限。

专题先补查 Fabric 已采用的版本，再持续接收更新，不依赖雷达最近一批的短窗口。修改研究范围会保留旧版并重新检查；暂停后从原位置追赶。过去的观察、问题和引用不会被新版改写。

当前有四个起步模板：管线登记、科研动向、商业指标、公共卫生。政策、监管、供应、区域等可以使用同一结构；方向标签不自动带来数据或专用算法。

- 管线比较原生登记状态和计划节点，登记号与药物项目分开。
- 科研累计去重材料和文字线索；研究是否独立、时间是否可靠另行记录。
- 商业与公共卫生数值必须有明确对象、单位、期间和口径。输入者声明的值与已经逐字段绑定原件的值分开。
- 正式公告、重要修订和撤回可以单独成为待核问题，不必等词频异常。资料缺失或采集失败不能解释成平静。

有依据的变化进入既有调查，程序保存材料和追加查找回执。页面提供本版观察草稿、历次记录、固定原件与下载；专家判断仍由研究人员提交。报告数量不是情报质量指标。

## 材料理解与判断更新

调查页面增加了“机器分析与调查过程”。系统把一个问题和本次采用的资料固定下来，按下面的顺序开展调查：

1. 读材料，提出有范围的命题，区分原文陈述与推断，指出支持、反面和限制证据。
2. 根据缺口提出最多两个查询，实际读取 Fabric 已采用的版本；没找到、读取失败和仍有更多结果分别保留。
3. 综合新旧材料形成有条件的回答，再做通用模型核验；明确发现问题时，最多修订并复核一次。
4. 当前稿通过通用核验后，才单独读取旧判断，说明维持或修订的理由。这一步只能生成比较说明，不能改动当前回答。没有通过核验，明确记录暂不能比较。

每版最多采用 10 个资料版本，正文片段合计最多 40,000 字符，首次分析通常调用模型三次，最多五次；有旧版时，核验通过后另加一次比较，通常四次、最多六次。完整模型请求另受 65,536 字节上限约束。引用不由模型抄写。程序把固定原文切成带编号的连续片段；模型只选择片段并说明关系，服务器从原文填入准确引文与位置。选中了真实片段，也不自动证明该片段支持命题，通用复核仍要核对含义。核验与修订直接读取程序绑定的引文对照表，并保留全文上下文，避免用原文其他位置的信息替错误引文补依据。模型核验与前两步使用同一配置，不是独立专家意见。

解读、综合、核验和修订只看本次问题、原件及实际检索结果，不接收旧机器稿，也不把首次解读重新当成原始材料。旧命题仅在最后的独立比较步骤使用；比较说明本身没有经过前面针对当前稿的通用核验。每版最多六条可单独核查的命题，引用不足时收窄结论，不把多项事实硬塞进一句话。

机器结果不写入研究人员判断，也不覆盖旧版。页面可以看实际查询、读原文和下载某一版；来源失去许可后，相关分析也不能继续读取。没有新材料或条件变化时，重复请求沿用已有分析。

自动线索和长期专题沿用每小时调查额度，关闭网页后仍可运行。手动分析另有次数上限；超时且无法确认模型是否完成时保留记录，不在后台反复发送同一请求。

## 连续运行的范围

- 原文及图谱的提交、发布位置和雷达处理位置保存在数据库。中断后核对原任务继续，不靠内存记进度。
- 重复版本不重复启动计算。同一线索的普通更新有冷却时间，调查次数按小时限制；等待预算的线索保留。
- 全库探索使用有上限的当前窗口，长期专题另存累计贡献。文字趋势有明确时间范围和计算预算，未纳入的部分会说明；窗口数量不能冒充全领域分母。
- 已采用资料被更新或撤回时，相关调查保留旧判断并提示复查。启用语义分析后，程序另存一版机器分析和变化理由，人工判断仍由研究人员提交。
- 旧库存逐步补录，新写入优先。磁盘低于保留空间时停止新增复制，并明确显示暂停原因。

zktest 的后台进程由 systemd 管理，PostgreSQL、Redis 继续使用原 Compose 数据卷。网页调试服务不随后台启动。具体启动、停止、重试和回退见[开发说明](docs/开发说明.md#持续运行与维护)。

## 已有能力和还缺什么

系统已经把持续取数、候选筛选、材料解读、有目的补查与机器分析更新接到同一调查。下表说明实际能力和限制；一次案例通过不代表已具备全领域判断水平。

| 环节 | 当前实际情况 |
|---|---|
| 来源、原文版本与持续运行 | 已运行，支持更新、恢复、固定原件和范围记录；来源覆盖仍不完整 |
| 对象与关系 | 能读取已有图谱并校验部分引用；可靠项目谱系、关系证据和历史身份仍不齐 |
| 候选线索 | 已有 11 类规则、统计、文本或图结构方法；部分方法须等合格输入，候选不等于结论 |
| 材料语义解读 | 已接模型解读固定原文，区分陈述、推断、否定与条件；输入可能只是摘要或局部原件 |
| 命题与证据比较 | 按命题保存支持、反对、限制及竞争解释，绑定原文；模型关系判断仍可能出错 |
| 调查规划与执行 | 根据缺口提出有理由的查询并实际执行；单轮最多两次，当前只读 Fabric 已采用版本 |
| 判断更新 | 后到材料触发新版机器分析；当前稿通过核验才比较旧命题，否则明确暂不能比较。旧版和人工判断各自保留 |
| 核验与效果评价 | 程序定位引文，模型做通用复核；专业评价与大样本独立效果评测仍待接续 |

已实现 ClinicalTrials、FDA CRL、Europe PMC 与 WHO 的公开读取；现役固定刷新只有 WHO 和 Europe PMC 的限定查询，其他来源不能据此称已常驻采集。旧库七类来源通过统一发布入口逐步进入版本库。当前自动补查主要查 Fabric 已采用版本。完整 WeKnora 取证、汪鑫怡的专业评价和潘倩的生成核验尚未接通；这些共享能力服务于雷达，不能代替雷达自身的研究组织与综合分析。

下一步扩大真实问题与来源覆盖，检查漏掉的反例、研究独立性和结论稳定性。数值与统计继续交给现有计算函数，模型承担文字理解和调查组织；不把通用模型检查写成已接通专业评价。

研究闭环的验收用一个真实问题贯穿：读懂原文及其限制，找支持与反例，针对缺口继续取证，给出有条件的分析，再用后来到达的新证据修订它。检查原文是否支持每条关键陈述、遗漏是否足以改变结论、计算和时点是否正确。材料数量、调查记录数量及工程测试通过数都不能代替这项验收。至少有一个资料足以回答的有限命题得到正确解释，能说明否定和适用条件；一条反例或不同解释影响判断，并说明下一次补查为什么必要。资料不足可以保留未知，但全部返回未知也不能证明已具备研判能力。
