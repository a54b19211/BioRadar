# BioRadar 项目说明

BioRadar 用于生物医药情报研究。它接收已有平台整理的资料，从中找出值得追查的变化，保存调查过程和依据，再把结果整理成可阅读的研究记录。

当前版本为 0.5，研究试用。学生的源码和运行环境统一放在 zktest 的 `/home/zk_test/zk_projects/BioRadar`。开发与交付统一使用 `main`。李明洋担任总负责人，孙博文负责研究逻辑，刘金彦负责页面和评测。

## 本分支新增：公开资料调查与历史研究

两库各有一个 `codex/historical-intelligence` 分支，在 zktest 的 `/home/zk_test/zk_projects/.bioradar-history/` 下联调。主目录和现役 Fabric 服务保持原版本，尚未合并部署。工作完成后沿原主线交接，不另留一套长期主代码。

Data-Fabric 新增公开读取、原始版本保存、历史档案导入与按时点读取。雷达新增历史研究入口：按明确清单读取资料、从原字段继续查找、保存事实与出处、固定预测，之后再读取结局追加评分。使用已有 PostgreSQL、RQ、调查和资料模型，没有新增工作流平台。

当前实际接入 ClinicalTrials、FDA CRL、Europe PMC；公开抓取由 Fabric 执行，雷达只读已采用版本。完整历史档案尚未取得，`external_archive` 保留导入口；教学历史只检验工程行为和计算，不能作为真实预测效果。

新的例子与命令见[开发说明](docs/开发说明.md#新的历史研究链路)。`scripts/history_e2e.py` 从两个实际 HTTP 服务运行，经过真实 PostgreSQL 和 RQ：一部分验证公开资料调查，一部分验证带明确答案的历史演示。页面入口为 `/history`，可创建研究、读原件、追加评分和导出。

这一版的概率是有明确定义的历史事件率基准，不是已经训练成熟的药物成功模型。资料不足就保留待核问题；没有合格历史资料就不给预测值。每次读取仍检查当前来源许可，保存原件不等于永久授权。完整多源调查、专业评价与真实多年效果验证继续按[开发分工](docs/开发分工.md)接续。

## 从真实调查例子开始

源码和环境在 zktest，交付后服务保持停止、数据卷保留。启动、连接和调试由开发者自行负责，必要命令见[开发说明](docs/开发说明.md)。本版增加一条无需网页的实际入口：只启动本项目 PostgreSQL，从同机 Data-Fabric 查已有登记资料，保存调查与结构化结果。

```bash
BIORADAR_DATA_FABRIC_URL=http://127.0.0.1:8100 \
  .venv/bin/python -m bioradar.ops.dig \
  --request contracts/examples/digging-clinicaltrials.request.json \
  --output artifacts/digging-result.json
```

10 月 16 日验收时，首查 `BCMA + myeloma` 采用了 6 条登记，结果尚有更多。程序从真实干预名派生 `LCAR-B38M`、`LCAR-BCX` 两次追加查找，均只读到已采用记录，没有新增材料。记录中有两条停止类状态、三条 UNKNOWN、一条招募中；停止理由不能直接解释为疗效失败。逐轮范围、原文引用、字段差异和缺口均保留，未生成研究人员判断。

这证明一次有限范围的调查可以运行并保存，不代表找到了新方向或完成全库监测。当前标题范围、派生规则与别名处理如何改进，是后续开发和评测的具体题目；输出是调查记录，不是自动专业研报。

## 再看教学例子

自行启动 API 和 Worker 后，可以运行已有教学例子：

```bash
make example
```

命令会载入一组明确标为教学材料的资料，实际计算一条线索，建立调查，加入支持和反面材料，保存前后两次判断。结果写入数据库及 `artifacts/example.json`；需要使用页面时再自行启动页面服务。再次运行会新建一项教学调查，保留已有记录。

真实研究使用同一套功能，换成取得许可的真实资料；教学例子的结论不能用于业务建议。

## 当前有哪些功能

| 部分 | 能做什么 |
|---|---|
| 资料 | 导入已有资料包，保留来源；比较两次取得的资料，查看新增、内容变化和本批未出现的记录 |
| 线索 | 运行 11 类现有方法，查看结果、计算范围和缺少的输入 |
| 调查 | 从线索或直接问题建立记录，追加材料、待办进度和研究笔记，暂停或继续 |
| 追查 | 用命令从 Data-Fabric 做最多三轮限定标题查找，由实际干预名派生下一查询，保存采用材料与缺口 |
| 判断 | 保存研究人员的判断及其依据；新材料加入后提醒重新检查，旧判断保留 |
| 方案比较 | 输入方案、目标和条件，检查资源门槛、差异及不同情景下的取舍 |
| 阅读 | 从调查返回本次采用的原文，查看历史，打印已保存的研究记录 |
| 历史研究 | 导入当时的队列清单，按合格历史资料计算基准；后续结局另存评分，预测不覆盖 |

资料比较只说明所选两批资料的差别；本批未出现不等于删除。线索不是专业结论，人工保存的判断也不等于已经通过专业审核。

调查支持人工补入材料，本版命令也可限定范围采用 Data-Fabric 资料。WeKnora 自动补查、汪鑫怡的专业评价、潘倩的生成核验还没有与雷达完整接通；正式报告发布和全库连续监测也需要继续做。这些状态在[资产盘点](docs/资产盘点.md)中逐项说明。

## 完整建设目标

系统既接受用户提出的研究问题，也要从持续增加的资料中主动发现线索。长期要回答：有什么新变化，什么会改变原有判断，什么需要及时核实。一次调查结束后继续保留依据，新材料出现时重新检查。

研究范围包括疾病需求与公平可及、技术证据、产业和供应链、经济支付与市场、人才平台与成果转化、监管和知识产权、政策实施效果，以及方案和资源配置。中央部门、地方政府、学校和企业可以有不同目标，来源事实和专业证据不随委托对象改变。

实际价值用真实问题检验：与现有问答、普通大模型和人工研究在同样资料、时间与审阅预算下比较，检查事实错误、遗漏反例、重复线索和研究人员花费的时间。技术演示与专业效果分别评价。
