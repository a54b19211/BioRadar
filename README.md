# BioRadar 项目说明

BioRadar 接收 Data-Fabric 整理的资料，计算变化和候选线索，继续查找相关材料，保存调查过程与依据。它也接受研究人员主动提出的问题。

源码统一在 zktest 的 `/home/zk_test/zk_projects/BioRadar`，主线为 `main`。李明洋负责集成与运行，孙博文负责研究逻辑，刘金彦负责页面和评测。4022 不保留开发副本。

## 现在怎样工作

徐子雯的程序保存新资料后，Fabric 在同一次数据库提交中记下待发布的变化。后台发布程序保存原文版本，雷达继续读取新版本、运行已有算法；符合条件的线索自动建立调查，补查相关材料并保存出处。没有新资料时不会反复计算全库。

这条链不要求先完成图谱。普通正文可以用于文本线索，临床登记的明确字段可以用于状态比较；唐蔚雯核实的对象、关系和时间资料到达后，再进入相应计算。PrimeKG 用作背景与查找方向，不能替代逐条研究证据。

后台把三件事分开：新取得了什么资料、什么值得调查、什么有依据判为紧急。旧资料补录不等于新近科研进展，登记终止不等于药物疗效失败，程序补查的材料也不自动成为支持证据或专家判断。

网页的“情报雷达”页可查看后台状态、已处理位置、候选和调查，也能暂停或继续自动读取。页面刷新只是读取状态；已有的手动分析、图谱调查和历史研究入口继续保留。

## 长期专题

“情报雷达”继续从新增资料里发现尚未指定方向的线索。“长期专题”持续记住一个明确问题：它采用过哪些资料，上一版看到什么，什么新证据需要继续查。两者使用同一套来源、调查和权限。

专题先补查 Fabric 已采用的版本，再持续接收更新，不依赖雷达最近一批的短窗口。修改研究范围会保留旧版并重新检查；暂停后从原位置追赶。过去的观察、问题和引用不会被新版改写。

当前有四个起步模板：管线登记、科研动向、商业指标、公共卫生。政策、监管、供应、区域等可以使用同一结构；方向标签不自动带来数据或专用算法。

- 管线比较原生登记状态和计划节点，登记号与药物项目分开。
- 科研累计去重材料和文字线索；研究是否独立、时间是否可靠另行记录。
- 商业与公共卫生数值必须有明确对象、单位、期间和口径。输入者声明的值与已经逐字段绑定原件的值分开。
- 正式公告、重要修订和撤回可以单独成为待核问题，不必等词频异常。资料缺失或采集失败不能解释成平静。

有依据的变化进入既有调查，程序保存材料和追加查找回执。页面提供本版观察草稿、历次记录、固定原件与下载；专家判断仍由研究人员提交。报告数量不是情报质量指标。

## 连续运行的范围

- 原文及图谱的提交、发布位置和雷达处理位置保存在数据库。中断后核对原任务继续，不靠内存记进度。
- 重复版本不重复启动计算。同一线索的普通更新有冷却时间，调查次数按小时限制；等待预算的线索保留。
- 全库探索使用有上限的当前窗口，长期专题另存累计贡献。文字趋势有明确时间范围和计算预算，未纳入的部分会说明；窗口数量不能冒充全领域分母。
- 已采用资料被更新或撤回时，相关调查保留旧判断并提示复查。程序只追加待核材料和变化说明。
- 旧库存逐步补录，新写入优先。磁盘低于保留空间时停止新增复制，并明确显示暂停原因。

zktest 的后台进程由 systemd 管理，PostgreSQL、Redis 继续使用原 Compose 数据卷。网页调试服务不随后台启动。具体启动、停止、重试和回退见[开发说明](docs/开发说明.md#持续运行与维护)。

## 用例与检查

| 要了解什么 | 入口 | 检验什么 |
|---|---|---|
| 商业、疫情指标、登记与真实通报 | `scripts/topic_sources_e2e.py` | 数值绑定、口径变化、登记变化和真实 WHO 通报进入调查 |
| 长期专题的建立、积累与改范围 | `scripts/topic_e2e.py` | 自动补查旧资料、跨期记录、暂停恢复和旧版导出 |
| 从源端落库到自动调查 | `scripts/monitor_e2e.py` | 只上传源资料，不调用雷达计算接口；检查自动计算、补查、暂停、重复与第二批 |
| 一次研究问题如何继续查 | `services/bioradar/ops/dig.py` | 从真实登记中的干预名派生下一查询，保留未找到和重复结果 |
| 图谱如何帮助找证据 | `scripts/graph_e2e.py` | 对象选择、关系方向、原文绑定、追加材料和旧判断复查 |
| 怎样避免历史回放偷看未来 | `scripts/history_e2e.py` | 按时点读取、固定队列及预测，后来另存结局与评分 |

测试资料明确标为教学材料，与真实来源分开。工程检查证明链路按要求运行，不能代替真实情报价值评测。详细验收集中保存在 `evaluation/handoff-verification.json`，不另建一套交接文档。

## 已有能力和还缺什么

当前已经运行的是持续取数、描述性线索、有限追查和研究记录保存。完整的自动情报研判尚未实现。下表按实际调用路径说明状态，接口、数据结构和计划中的阶段不算已运行能力。

| 环节 | 当前实际情况 |
|---|---|
| 来源、原文版本与持续运行 | 已运行，支持更新、恢复、固定原件和范围记录；来源覆盖仍不完整 |
| 对象与关系 | 能读取已有图谱并校验部分引用；可靠项目谱系、关系证据和历史身份仍不齐 |
| 候选线索 | 已有 11 类规则、统计、文本或图结构方法；部分方法须等合格输入，候选不等于结论 |
| 材料语义解读 | 尚未接入雷达自动调查主链；Fabric 已有实体关系抽取代码，不能替代针对研究问题的理解 |
| 命题与证据比较 | 尚未形成运行闭环：没有持续判断材料对具体命题的支持、反驳、限制和替代解释 |
| 调查规划与执行 | 能按明确词项有限补查、采用原件并保存回执；尚未根据研究缺口选择下一问题并反复评价 |
| 判断更新 | 能保存人工判断版本、提示复查并按给定条件比较方案；尚未自动形成、比较和修订有依据的机器分析草稿 |
| 核验与效果评价 | 工程链路已验证；专业核验服务和独立的语义、遗漏、判断质量评测仍未完成 |

公开读取器已接 ClinicalTrials、FDA CRL、Europe PMC 与 WHO 通报；旧库七类来源通过统一发布入口逐步进入版本库。当前自动补查主要查 Fabric 已采用版本。完整 WeKnora 取证、汪鑫怡的专业评价和潘倩的生成核验尚未接通；这些共享能力服务于雷达，不能代替雷达自身的研究组织与综合分析。

下一步优先贯通材料解读、命题证据比较、调查规划和判断更新。数值与统计继续交给现有计算函数；模型承担文字理解、候选解释和工具选择。原文声称、模型推断、专业评价及人工确认分别保存。新增资料时要能说明上一版哪些理由改变了，而不只是把旧记录标成待复查。

研究闭环的验收用一个真实问题贯穿：读懂原文及其限制，找支持与反例，针对缺口继续取证，给出有条件的分析，再用后来到达的新证据修订它。检查原文是否支持每条关键陈述、遗漏是否足以改变结论、计算和时点是否正确。材料数量、调查记录数量及工程测试通过数都不能代替这项验收。至少有一个资料足以回答的有限命题得到正确解释，能说明否定和适用条件；一条反例或不同解释影响判断，并说明下一次补查为什么必要。资料不足可以保留未知，但全部返回未知也不能证明已具备研判能力。
